# Experiment table

CER = Whisper large-v3 character error rate on the 88-sentence benchmark (lower is better). Hinglish CER is a rough score: Hindi Whisper against AI-drafted Devanagari references (checked by me). "Sim" = ECAPA speaker similarity to my reference clip in the same language. Single-seed numbers come from one run (seed 1234); 3-seed numbers average seeds 1-3 with a paired bootstrap 95% interval over sentences. A crashed sentence counts as CER 1.0. Every number links to a file in [`results/`](../results).

| # | Experiment | Hypothesis | Change | Result | Conclusion |
|---|---|---|---|---|---|
| E0 | Pretrained XTTS-v2, raw text | The pretrained model handles Indian text as written. | Baseline: my 3 reference clips, no text processing | 8 of 12 Hindi rows crash (XTTS's digit expander fails on Hindi). CER en 0.115, hi 0.960, Hinglish 0.485 ([single_seed](../results/single_seed.md)) | Raw text isn't usable. A text normaliser is required before anything else. |
| E1 | Pretrained + normaliser | Writing numbers, ₹ and acronyms out as spoken removes crashes and misreadings. | Numbers, ₹, dates, times, acronyms written out as spoken | No crashes. 3 seeds: CER all 0.125, en 0.037, hi 0.198, Hinglish 0.400; sim en 0.502 ([summary](../results/summary.md)) | The baseline every fine-tuning claim is measured against. Hinglish is the worst part. |
| E2 | Fine-tune on session 1 (16 min), pick checkpoint by val CER | 16 min of my voice moves accent and voice; val CER can pick the checkpoint. | 1000 steps; lowest val CER on 8 en+hi clips | Picked step 250. Sim en 0.718 vs E1 0.497; CER Hinglish 0.311 vs 0.431 ([single_seed](../results/single_seed.md), [selection](../results/runs/E2/select/selection.csv)). I listened: robotic, not my voice, despite the high similarity | **Failed.** The pick was barely trained; CER on 8 clips is too noisy to choose by. Changed the rule to lowest val loss with CER and duration guards. ECAPA similarity (0.718) didn't catch the robotic sound, so it measures speaker identity, not naturalness. Without the normaliser it also read raw digits worse than E0. |
| E2b | Session 1 only, E3's recipe | If data amount matters, E3's recipe on less data does worse than E3. | Same 2000-step target and selection rule as E3, less data (208 vs 316 clips) | Both runs picked step 1000; val loss rises after it ([run 1](../results/runs/E2b_run1/select/selection.csv), [run 2](../results/runs/E2b_run2/select/selection.csv)). 3 seeds vs E3: E3 − E2b overall +0.002 [−0.016, +0.022]; en +0.008 [−0.015, +0.034]; hi +0.035 [−0.003, +0.094]; Hinglish −0.045 [−0.076, −0.017] ([bootstrap](../results/bootstrap_E2b_vs_E3.txt)). Sim en 0.721 vs 0.730. Run 1, single seed: CER en 0.028, hi 0.062, Hinglish 0.263 ([single_seed](../results/single_seed.md)) | The extra 8 minutes (mostly Hindi and Hinglish) only measurably helped Hinglish. English and Hindi CER can't tell 16 and 24 minutes apart. E2's bad result was the checkpoint pick, not the data. Run 2 didn't reproduce run 1 bit for bit (same pick, val loss at that step within 0.002). |
| E3 | Fine-tune on sessions 1+2 (24 min) | More data (24 min) and longer training improve voice and intelligibility over E1. | 316 train / 17 val clips, 2000 steps, val-loss rule | Picked step 1500 (2000 failed the CER guard). Run 2 reproduced run 1's selection table exactly. 3 seeds: CER all 0.084 vs E1 0.125, −0.041 [−0.083, −0.009]; Hinglish 0.222 vs 0.400; en and hi within noise; sim en 0.730 ([bootstrap](../results/bootstrap_E1_vs_E3.txt)) | Fine-tuning moves the voice a lot and helps Hinglish. Listeners preferred it for voice match 15 of 16. English name rows got worse (0.030 → 0.106, +0.076 [+0.005, +0.193]); all names together are within noise. |
| P7 | Hinglish via Devanagari at inference (the failure fix) | XTTS reads Hinglish badly because Roman script goes through its English front-end; Devanagari through Hindi fixes it. | IndicXlit + a small lexicon turn Roman Hinglish into Devanagari, sent to XTTS as Hindi | On E3: Hinglish CER 0.222 → 0.098, −0.124 [−0.177, −0.068]; held-out 10 sentences 0.205 → 0.119, −0.086 [−0.146, −0.034] ([bench](../results/bootstrap_E3_vs_E3_deva.txt), [held-out](../results/bootstrap_E3_heldout_en_vs_E3_heldout_deva.txt)). Listeners chose it 4 of 4 | **Kept.** The route gives most of the intelligibility (pretrained + route is 0.097); fine-tuning gives the voice. |
| E4 | Train Hinglish as Devanagari | Training on Devanagari Hinglish beats transliterating only at inference. | Same audio, Hinglish transcripts transliterated and tagged Hindi | Held-out Hinglish 0.126 vs E3 + route 0.119, +0.007 [−0.016, +0.032] ([bootstrap](../results/bootstrap_E3_heldout_deva_vs_E4.txt)) | No gain, and IndicXlit mistakes go into the training text. Dropped. |
| E5 | Sampling sweep | Lower temperature or top-p cuts word errors. | Temperature 0.75/0.5/0.3 × top-p 0.85/0.7, 3 seeds, val + held-out only | Val CER 0.019-0.028, held-out Hinglish 0.107-0.123, no setting best on both ([sweep](../results/runs/E5_sweep_long/sweep.csv)) | Within noise. Kept the defaults (0.75 / 0.85). |
| E6 | Split long sentences | Splitting long sentences reduces errors on them. | Split above 120 characters, 0.25 s gap; 5 new long sentences | CER en+hi 0.0088 unsplit vs 0.0175 split; Hinglish 0.140 vs 0.143 ([long](../results/runs/E5_sweep_long/long.csv)) | Doesn't help. Off. |
| E7 | Inference-only name fixes | Names fail from sampling noise, English-style spelling or babble, so a lower temperature on name rows, a respelling list or a retry on over-long clips fixes some of them. | Temperature 0.3 on name rows; a respelling list (written from pronunciation before any synthesis); a babble guard (retry with another seed if a clip runs over 1.5× the usual length). Tuned on 20 new held-out name sentences, 3 seeds | Name words missed: base 0.34, temperature 0.39, respelling 0.46, all three 0.40. CER differences all within noise (e.g. temperature −0.003 [−0.016, +0.010]). The guard never fired ([block15_heldout](../results/block15_heldout.md)) | **Failed.** Nothing beat the final pipeline, and respelling made names worse, so nothing was adopted. The benchmark run was skipped because it would equal Final. |
| E8 | Fine-tune with name clips upweighted | More exposure to names in training makes the model say them better. | E3's recipe with the 39 English training clips that contain names repeated 3× (394 training rows); same val-only selection (picked step 2000) | Held-out names: CER 0.029 vs 0.037, −0.008 [−0.022, +0.007]; name words missed 0.37 vs 0.34 ([block15_finetune](../results/block15_finetune.md), [selection](../results/runs/E8_names_ft/select/selection.csv)) | **No gain.** Doesn't beat Final on held-out names; Final kept. Repeating the same 39 clips isn't new name data; real name recordings are the next step. |
| Final | E3 + normaliser + Devanagari route | E3 plus the adopted fixes beats the pretrained baseline. | Default sampling, no splitting | 3 seeds: CER all 0.061 vs E1 0.125, −0.064 [−0.110, −0.025]; Hinglish 0.098 vs 0.400, −0.303 [−0.392, −0.215]; en and hi within noise ([bootstrap](../results/bootstrap_E1_vs_Final.txt)) | The shipped system. Main remaining weakness: names. |
